## Space Race — Milestone 1

Start with `projects/spacerace/HANDOFF.md` for current state and continuation notes. Buildless entry `projects/spacerace/index.html`; `config.mjs` centralizes feet-to-metres settings, `simulation.mjs` owns speed/distance, fixed particles, ring recycling and controller input, `particles.js` supplies a single instanced quad batch, and `main.js` integrates Three.js/XR/HUD. Reuses Forest's MIT Three.js r180. `npm run test:spacerace` and root `npm test` cover the simulation. See the project README for controls and validation limits. Keep local relative imports and increment changed entry/import query versions when updating cached runtime code.

`CONFIG.targetFrameRate` is 120; the user compared 90 FPS at the browser default against 120 FPS with the request and asked to retain it. Requests for 120 Hz are made via `xr-frame-rate.mjs` when advertised by the session; the request is fired without awaiting it after rendering the first visible tracked XR frame. Unsupported/rejected/stalled requests cannot block startup or the render loop. Actual frame rate requires headset checking. Maximum speed is now 300 mph (440 ft/s, 134.112 m/s), with acceleration/braking unchanged at 60/100 ft/s². Right trigger/Up accelerates, left trigger/Down brakes; analog simultaneous inputs combine, release coasts. Environment moves +Z while the camera stays tracked; initial XR eye position/yaw anchors the fixed flight axis once, with no steering. Visible/tracked frames only, capped delta and no catch-up. Session entry/exit resets speed/field. Five uniformly spaced rings initially extend 1,000 feet ahead (`ringCount: 5`), independent of particle range; camera far clipping covers the full sequence. Particle radial range is 10–200 feet from the fixed flight axis, sampled uniformly by annular area, with 500-foot forward reach unchanged. One instanced particle batch (3,000 pool, shader density fades and travel-axis stretching), one instanced annulus batch and one canvas HUD in XR. HUD follows the viewer smoothly; HTML stats on desktop. `frame-rate.mjs` averages uncapped animation-loop intervals over half-second windows, resets across inactive periods/session changes, and displays app FPS in both HUDs (not compositor/GPU timing). No lighting, bloom, external assets or gameplay. `ring-audio.mjs` now adds generated filtered-noise whooshes: two fixed HRTF rim emitters per pooled ring, radial-velocity Doppler, speed/proximity gain and a rear fade before recycling. User gestures unlock Web Audio without gating XR startup; Sound toggle mutes, inactive/session transitions silence. Tunable reach/frequency/low-pass/volume are in config. Lower-pitched sound uses a broad 350 Hz band and gentle 1,200 Hz low-pass; master gain 0.325 is half the original 0.65. Audio quality and its effect on 120 FPS require headset testing. Physical Quest stereo, visual comfort and sustained frame-rate checks remain pending; desktop checks cannot establish them. Existing Blender backups are unrelated and must remain untouched.

Space Race ring-wake release (user accepted and authorized publication): `rings.js` preserves opaque leading annuli and adds one instanced, double-sided single-pass additive cylinder batch, eight longitudinal segments. Shared instance matrices guarantee identical recycling. Wake length uniform is speed × 12/120; linear shader alpha 1→0 along -Z into the distance; hidden at zero speed. Four named `RING_WAKE_*` config exports control it. Adds one moving-scene draw batch; no postprocessing/radial softness or changes to particles/input/HUD/audio.
