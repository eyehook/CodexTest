## Terrain — Milestone 1

Source in `src/terrain/`; read `projects/terrain/README.md`. Reuses the shared bundled Three.js r180, with no additional runtime dependencies. Root scripts: `pnpm dev:terrain` (5174), `pnpm build:terrain`, `pnpm test:terrain`; root `test` includes Terrain. Vite config lives in `projects/terrain/`, outputs static `index.html` and `build/` there; preserve source and build together for Pages. Follow the repository’s local-test-then-publish workflow.

One indexed circular mesh, central fan, adaptive sector counts and exponential ring spacing. Static geometry, GPU gradient-noise displacement; CPU doubles split each octave into unsigned lattice and fractional coordinates, matching GLSL uint hashing. Ground height subtracts directly; near detail is full, distant octaves attenuate by vertex spacing. Four finite-difference height samples provide normals. Terrain frustum culling disabled. Left stick head-relative walking at 6 m/s; right stick smooth turning up to 60°/s around the tracked headset (15% horizontal deadzone), plus physical turning and room-scale ground following; desktop pointer lock/WASD. Camera is parented to a pivot-compensated yaw rig, reset on XR session boundaries. Terrain color uses absolute-height bands scaled by amplitude: sandy shore below 14%, three hill greens at 14/25/35%, cool white snow at 43%, bright white summits at 53%, each with a narrow 1.5% transition. `colorAmplitude` updates with terrain settings; stronger directional shading is retained. Debug controls explicitly apply topology changes. Startup/button GPU readback compares actual vertex heights against JS including ±1e9 m. Diagnostics update during XR in hidden DOM for remote inspection. Quest comfort, stereo/controller behavior and 72 FPS target still require physical testing. Never claim these from desktop checks.

Terrain water: one opaque blue, double-sided 128-triangle disk at `amplitude * 0.1` (6.5 m default); uses the nominal amplitude, not sampled peaks or octave sums. Static vertices; radius scales on explicit mesh rebuild and Y subtracts ground height each frame, matching terrain coordinates. Three.js fog matches the custom terrain fog. Initial spawn searches nearby dry ground; reset still returns to origin. No swimming/buoyancy/collision changes. `src/terrain/water.mjs` isolates level/spawn logic. Adds one draw call per eye.

## Terrain trees — Milestone 2

`src/terrain/trees/TreeGenerator.mjs` uses cell-coordinate hashing and a local PRNG (no Math.random): 64 m cells, seed 74921, 55% cluster probability, 1–2 clusters, radius up to 20 m, 48 candidates per cluster. Clusters cross source boundaries. `bands.mjs` shares unchanged color/water thresholds: trees are admitted above beachEnd (15.5% amplitude), below snowStart (43%) by default. Explicit limits are supported; the minimum cannot override the beach exclusion. Positions/heights/sizes/colors reproduce independently of traversal.

`TreePopulation` caches a bounded square of source cells covering the 800 m streaming radius plus cluster/cell margin. Generates entering cells, evicts departed cells, rebases and uploads only on cell changes or explicit generation/terrain-height changes. JS doubles retain absolute positions, GPU attributes store cell-anchor-relative X/Z, absolute ground Y, size and color. `TreeSystem.js` draws one three-vertex `InstancedBufferGeometry` batch with culling off. `TreeMaterial.js` computes player-relative positioning and upright per-eye billboarding; fully opaque triangles pop in/out at a 700 m cutoff; depth testing/writing on, no alpha fading or dithering (clamped within terrain radius). Sizes 3–8 m; width 0.52 × height with 0.8–1.2 variation; 0.25 m base sink. No per-frame instance buffer uploads or per-tree transforms, textures, trunks, animation, lights, shadows or collisions.

`TreeControls.js` appends tree controls to the existing panel. Show/hide is immediate; other settings use Apply. Overlay adds loaded tree/cell counts, actual render callbacks (one tree draw per desktop frame; XR one per eye expected), and cumulative buffer uploads. Initial spawn loads 5,046 trees/841 cells, 2,302 within cutoff distance before view/terrain occlusion. Tests in `tests/terrain/trees.mjs` cover determinism, clusters/margins, elevation restrictions, caching/eviction/revisits, ±1e9 m precision and instance-buffer update versions. Keep build output with source. Desktop browser checks do not validate physical Quest stereo, cutoff behavior, anchoring, streaming frame-time spikes, or 72 FPS; these remain pending. Changes are local until the user explicitly requests publication again.


Terrain flight: `src/terrain/flight.mjs` reuses `projects/forest/forest-flight.mjs` unchanged (Quest xr-standard A/right or X/left button 4). Hold applies 4.5 m/s² thrust against 1.5 m/s² gravity, capped at ±1.5 m/s; release retains momentum, adds up to 0.75 m ascent, then descends. Both buttons do not stack. `flight.mjs` preserves absolute world altitude while airborne and converts it to clearance against the current terrain for Forest integration/landing. Crossing a ravine changes clearance without changing altitude; rising ground clamps landing and resets velocity. Grounded walking follows terrain. `main.js` raises rig Y by clearance, preserving physical tracking, water and tree coordinates. Flight pauses unless XR is visible and tracked. Session start/end and Return to origin reset height/velocity. Desktop controls remain unchanged. Diagnostics include flight height/vertical speed; `tests/terrain/flight.mjs` checks input/gating/coasting/landing. Physical Quest flight/comfort validation remains pending.

Terrain travel-speed control: `updateTravelSpeed` in `player.mjs` reads xr-standard analog trigger index 0, right increases/left decreases horizontal speed at up to 3 m/s per second, bounded 0.5–25 m/s. 5% idle deadband, analog pressure, equal dual input cancels, release retains selection. Visible/tracked XR only; A/X flight stays independent. `main.js` updates `c.speed` and syncs diagnostics/debug input (including on XR exit). Tests cover hand/mapping, analog pressure, limits, gating and frame-rate independence.
