# Fishing — Fishing simulator foundation

Fishing starts as an independent copy of Terrain, preserving its current functionality. Fishing now includes rods, physics-based casting/retrieval, articulated leaders/hooks, and a first nibble/bite/catch loop. All application modules and tests are duplicated so the projects can diverge; Three.js remains the existing licensed vendor dependency. Flight physics are copied into `src/fishing/flight-physics.mjs`.

A single GPU-displaced radial mesh represents a deterministic landscape, with a flat blue water surface forming lakes. Milestone 2 adds clustered, instanced triangle trees. No textures, shadows, wind, collisions, or postprocessing. Runtime dependencies are local, licensed Three.js r180 from `shared/vendor/three-r180/`; Vite is the only development dependency.

## Run and build

From the repository root:

```sh
pnpm install
pnpm dev:fishing
pnpm test:fishing
pnpm build:fishing
```

npm equivalents are `npm install`, `npm run dev:fishing`, `npm run test:fishing`, and `npm run build:fishing`. Development runs at http://localhost:5175/. The isolated Vite server serves Fishing; use the root static server to test the project directory link.

The build writes `projects/fishing/index.html` and `projects/fishing/build/`. Keep these generated files alongside `src/fishing/` when publishing. Relative asset paths work under GitHub Pages' `/CodexTest/` prefix. No installation is needed to run the checked-in static build:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://localhost:8080/projects/fishing/. The existing USB Quest launcher also serves this URL.

## Desktop and Quest

Desktop: click the landscape for pointer-lock mouse look, WASD to walk, Escape to release. Eye height is 1.7 m. Diagonal movement is normalized. Debug inputs do not trigger walking.

Quest 3: serve on HTTPS (GitHub Pages) or use the existing USB/ADB localhost forwarding setup; open in Meta Quest Browser and choose **Enter VR**. `local-floor` tracking preserves physical headset height. The left thumbstick moves relative to horizontal headset facing with a radial 15% deadzone. The right thumbstick turns smoothly about the tracked headset at up to 60°/s with a 15% horizontal deadzone. Physical turning also works. Walking speed comes from the terrain settings (6 m/s default); controller triggers do not adjust it. Movement pauses during hidden/untracked XR frames. Room-scale horizontal tracking also samples the corresponding world ground. Hold **A** (right) or **X** (left) to fly upward; release to coast to an apex and drift back down. Either or both buttons apply the same thrust. Fishing uses its own flight tuning: 7.5 m/s² upward thrust against 1.5 m/s² gravity, giving 6 m/s² net ascent acceleration and a 3 m/s ascent limit (both twice the original ascent). Descent remains capped at 1.5 m/s. Releasing full ascent adds up to 3 m over two seconds before descent. Airborne flight stores absolute world altitude: crossing a valley changes ground clearance, not flight altitude. Only thrust and gravity change airborne altitude until the terrain is reached. While airborne, horizontal velocity smoothly approaches the thumbstick target at a response rate of 4/s. Easing the analog stick toward centre slows with gentler 0.8/s drag instead of snapping velocity to the reduced input. Fully releasing preserves world direction and leaves about 20% of speed after two seconds (4% after four seconds), with up to 7.5 m of total glide from 6 m/s. Head turns alone do not rotate an existing glide. Grounded release stops immediately; landing clears horizontal momentum. Hidden/untracked frames pause it. Grounded walking follows the terrain; landing on rising terrain clamps to ground height and resets vertical speed. The camera rig rises while terrain, water and tree heights remain consistent, and physical headset tracking height is preserved. Flight pauses during hidden/untracked XR frames. Entering/leaving VR and Return to origin reset flight height and both vertical and horizontal momentum. Flight uses controller buttons only; desktop WASD is unchanged. Exit VR restores desktop controls.

Publishing follows this repository's existing workflow: test locally/on Quest, then commit and push to `main` when requested. Pages serves the root of `main`. Published path will be `https://eyehook.github.io/CodexTest/projects/fishing/` after deployment.

## Controls and parameters

Expand **Terrain controls**. Apply explicitly to change parameters. Radius/rings/angular segments rebuild geometry only when their values change; movement never rebuilds or uploads geometry. Wireframe toggles immediately. Reset returns the logical offset to the origin (which may be underwater). The initial viewpoint starts on nearby dry terrain when available. Settings last for this page session.


Controls expose radius, rings, angular segments, amplitude, frequency, octave count (1–8), persistence, lacunarity, seed, walking speed, turning speed, fog distances, and fog/sky colors. Fog end is clamped inside the terrain radius, with start below end. Matching fog/sky colors best conceal the horizon. Initial defaults are in `src/fishing/height.mjs`: 2,000 m radius, 128 rings, up to 256 angular segments, seed 12345, 65 m amplitude, frequency 0.002, five octaves, persistence 0.48, lacunarity 2, 6 m/s walking speed and 60°/s smooth turning.

Water is a static, opaque blue disk at 10% of the configured terrain amplitude: 6.5 m by default. This uses the nominal amplitude, not the highest sampled hill or the sum of noise octave amplitudes. Its world level changes only when amplitude changes. The disk is translated by the same ground-height adjustment as the terrain; no water vertices or topology are updated during movement. Fog matches the terrain. There are no waves, reflections, swimming, buoyancy or collision changes; walking still follows the ground, including beneath lakes.

Terrain colors follow absolute world elevation, so they remain fixed as you walk. Relative to terrain amplitude, sand extends from the waterline (10%) to 14%; green bands begin at 14%, 25%, and 35%; cool white snow starts at 43%, and bright white summits at 53%. Narrow 1.5% transitions soften jagged boundaries while retaining visible bands. Thresholds scale with amplitude and do not sample changing local peaks. Coloring adds no geometry or draw calls.

## Implementation

- `mesh.mjs`: one indexed mesh with a dense eight-sector central fan and exponentially expanding rings. Ring populations grow in multiples of eight up to the angular cap, avoiding needle-like central triangles. Unequal ring populations are joined with a seam-closing zipper. Topology stays static during movement.
- `height.mjs`: matching JS/GLSL seeded eight-direction gradient noise with quintic interpolation, layered into rolling hills. JS logical coordinates use doubles. Every octave splits the offset into a fractional cell position and unsigned 32-bit lattice coordinates **before** upload. Integer hashing wraps at 2^32 lattice cells; no small permutation-table repetition. This is effectively infinite, not mathematically aperiodic. ±1 billion meter positions are covered by tests; arbitrary double limits are not promised.
- `material.js`: static X/Z vertices, GPU height displacement, direct subtraction of CPU ground height, four extra height samples for smooth finite-difference normals, inexpensive ambient/sun lighting, distinct elevation bands (sand near the water, three greens for hills, cool white snow and bright white summits), and atmospheric haze. Octaves fade smoothly as frequency × local vertex spacing grows. This changes rendered distant geometry, never the underlying world definition. Near-center detail remains unfiltered. Culling is disabled because CPU bounds do not describe displaced terrain.
- `water.mjs`: fixed world water level, matching local elevation adjustment, and deterministic search for a nearby dry initial viewpoint. One additional static 128-triangle disk and one additional draw call per eye.
- `bands.mjs`: shared height-color thresholds used by terrain, water and tree generation.
- `trees/TreeGenerator.mjs`, `TreeSystem.js`, `TreeMaterial.js`, `TreeControls.js`: deterministic clusters, bounded cell streaming, one instanced billboard batch, hard distance cutoff and debug controls.
- `flight.mjs`: gates Forest’s shared A/X flight integrator on visible, tracked XR frames; main applies clearance to camera-rig Y without changing world heights.
- `player.mjs`: shared head-relative movement and Quest controller axes; `main.js`: initialization, XR/desktop lifecycle, debug controls, and frame loop.
- `check.js`: actual GPU vertex shader evaluation rendered to an RGBA8 target and read back. Packed height quantization is approximately 0.00012 m; comparison tolerance is 0.003 m. Startup and the check button compare JS and GPU at positive/negative and ±1 billion meter coordinates. Checks run outside immersive rendering.

Default geometry uses fewer than the nominal 65,536 triangles because inner rings adapt their sector count. Exact counts appear in diagnostics. One terrain draw call per eye, static position/index buffers, no per-frame topology changes. GPU cost includes five noise evaluations per vertex for displacement/normals; profile this on-device before increasing complexity. Far geometry can still morph under movement; filtering reduces this but does not eliminate radial resampling artifacts. Direct ground following can be uncomfortable on slopes and needs headset evaluation.

## Milestone 2: triangle trees

Each tree is one upright, camera-facing triangle with a solid green color; no trunk, texture, animation, shadow or collision. Heights vary deterministically from 3–8 m and widths from about 42–62% of height, using a five-green palette with subtle variation. Cylindrical billboarding uses each eye’s camera position and rotates only around the vertical axis. Turning, physical movement and terrain-following share the existing world coordinates and elevation subtraction.

World cells are 64 × 64 m by default. An integer hash and local seeded generator determine zero, one or two clusters per cell. A 55% cluster probability, 20 m maximum radius and 48 candidates per cluster create irregular clumps with clearings. Clusters extend across their source-cell edges; source cells beyond the visible area are retained so edge clusters are not clipped. Terrain filtering rejects candidates before buffering. Default minimum elevation is the **end** of the beach-to-grass transition (`amplitude × 0.155`, 10.075 m); maximum is the start of snow (`amplitude × 0.43`, 27.95 m). These constants are shared with the color shader. Placement always uses the exact CPU terrain height at the tree’s world coordinates. A 0.25 m base sink helps hide the horizontal base on sloping ground.

The system loads source cells around an 800 m streaming radius with an extra cell/cluster margin. Trees are fully opaque through 700 m and pop out beyond that distance; there is no alpha fade or dithering. If you reduce the terrain radius, the cutoff is clamped inside that mesh. Depth testing and depth writing are enabled, so overlapping trees occlude correctly without transparency sorting. Atmospheric fog matches the terrain.

CPU generation and buffer uploads happen only when crossing a cell boundary, changing generation settings, or changing the terrain noise/height settings. Retained cells are reused; old cells are evicted. A buffer contains small offsets from the current cell’s double-precision anchor, preserving submeter placement during long travel. Ordinary frames update only uniforms and the batch origin; no per-tree matrices or transforms are updated. Disabling trees suspends streaming until enabled again. Tree geometry is three shared vertices and one instance per tree, with frustum culling disabled and one draw call per eye.

Expand **Terrain controls → Trees** for show/hide, density, streaming distance and size. Advanced numeric fields also expose seed, cell size, cluster probability/radius, width ratio, elevation limits, cutoff distance and base sink. Show/hide is immediate; other values take effect with **Apply terrain settings**. Blank elevation fields follow beach/snow thresholds automatically; a manual minimum is still clamped above the beach. Maximum elevation can be overridden, including to permit snowy trees. Cutoff remains inside the streaming radius, and max height is at least min height. Settings last for the page session. High density, small cells or a large streaming radius increase generation cost and instance count.

The overlay reports active (loaded) tree count, active source-cell count, tree draw calls for the last frame, and cumulative instance-buffer uploads. Flight clearance, absolute world altitude and vertical speed also appear in diagnostics. Active trees include the margin and those outside the camera view; this is not the number of visible silhouettes. At the default starting position, deterministic generation loads 5,046 trees in 841 cells, of which 2,302 fall within the 700 m cutoff before camera/hill occlusion. Upload count stays fixed during movement within a cell. Desktop rendering confirms one tree draw call; XR should show two total per frame, one per eye, and needs physical verification. These are instrumentation checks, not a Quest performance benchmark.

## Lighthouse landmark

`src/fishing/assets/Lighthouse.glb` is copied from the user's Blender export, displayed at twice its exported size with its original materials. `Lighthouse.js` loads it through the existing local GLTFLoader. A deterministic search selects elevated land within 240 m of the initial dry spawn and within 108 m of sampled water; default position is X −171 m, Z −60 m, about 113 m from spawn and 24 m above water. The desktop view initially faces it. Terrain height/noise changes recompute placement; walking never moves it in world coordinates. Flat/coastless settings use a stable fallback without a coastline guarantee.

The authored empty node `Base` defines the terrain contact point in all three axes, accounting for exported parent transforms and the retained 2× model scale. The model's lower geometry extends into the terrain; no separate foundation is generated. Terrain changes recompute placement and walking preserves the fixed world anchor. The model uses ambient/directional lighting, fog and normal depth testing; no collision, beam animation or extra shadows. The asset is emitted into `projects/fishing/build/` by Vite. Tests in `tests/fishing/lighthouse.mjs` cover actual GLB loading, Base anchoring, transformed node hierarchies and world rebasing. Physical Quest appearance remains to be checked.


Fishing grass: `src/fishing/grass/` uses a fixed pool of 156 terrain patches, each 8 m square with up to 320 blades (49,920 instance slots, within the 50,000 cap). One jittered candidate per 0.5 m × 0.4 m rectangle creates uniform world density on green land only, above beachEnd and below snowStart. A 2 m shader edge shrink limits visibility to 150 feet (45.72 m). Patch selection includes a conservative movement margin, preserving the full circle between 2 m refreshes; invisible margin blades still occupy slots. Terrain placement is deterministic and available everywhere as the player travels. Heights are 9–21 cm with varied widths, angles and greens. No textures, wind, shadows or collision.

CPU streaming: preallocated patch objects, typed request/free arrays and dirty flags replace per-blade Maps/Sets, distance selection and sorting. Retained patches keep their slot; only entering patches generate heights, bounded to 128 candidates per frame, nearest unfinished patches first. Patches generate over multiple frames and upload only on completion. A single instanced interleaved GPU buffer packs position, size, color and orientation. Dirty patch blocks use one merged upload range, preserving changes not yet rendered. Ordinary frames update uniforms only, except rare coordinate rebasing beyond 1,024 m. New/teleported areas fill progressively; invalidating terrain clears old blades. No worker is used in this version.

Grass comparison: The Terrain controls checkbox or G on desktop toggles rendering and streaming. B/Y have no grass action. A/X flight is unchanged; controller triggers have no speed action. Hidden DOM diagnostics report submitted eligible blades (including the margin), selection/generation/buffer preparation CPU milliseconds (S/G/B), total/peak grass update time, queued patches and upload count. These timings exclude GPU execution and driver work during rendering. Unit tests cover fixed-pool coverage, biome exclusion, reproducibility, per-frame generation budget, retained slots, consolidated uploads, toggle suspension, teleports and billion-metre rebasing.

Three desktop 1,800-frame walking CPU checks measured total grass-update time of 45–87 ms before versus 9–19 ms with fixed patches (roughly 80% lower in these samples). This is a local Node CPU check, not a headset FPS or GPU benchmark. All grass uses one double-sided opaque draw batch; fixed slots can process more invisible triangles than the previous selection. Quest appearance, CPU/GPU balance and performance still need physical comparison.


### Seed changes and coastal respawning

Applying a different seed searches for a dry coastal spawn rather than leaving the player at the old coordinates. The spawn is 1 m above the waterline at normal amplitudes (scaled down for low amplitudes), with a verified water sample within 96 m. Search is deterministic and uses the newly applied terrain settings. Flight height, vertical velocity and horizontal glide are cleared; tracked headset X/Z is compensated so the actual viewer lands at the chosen point. If no dry coast is found (including zero-amplitude terrain), the terrain settings are restored and an explanatory status is shown. Applying the same seed does not relocate the player. Initial loading and Return to origin retain their existing behavior.


## Fishing rods — first prototype

Press B on the right Quest controller or Y on the left to show/hide the rod on that hand; showing it hides the other hand's rod. Both begin hidden and reset on VR exit; temporary controller-source replacement preserves the equipped hand. Each procedural 2.1 m rod uses one tapered, solid dark gray mesh shaped around a continuous arc-length centreline, plus a cork-style grip. `RodSystem.setBend(hand, tension)` accepts 0–1 for future fish load/reeling integration; stronger bends accumulate toward the tip. No Blender asset is required.

A segmented 2-foot (0.6096 m) minimum line connects the animated tip to a 9 cm red/white spherical bobber simulated under gravity, inertia and drag. Controller grip poses, rig turning and flight move the whole assembly consistently. Missing controller poses hold the last known world pose indefinitely while tackle physics and encounter timers continue. B/Y use xr-standard button index 5 with independent edge detection; A/X flight remains on index 4. Casting/reeling now use the equipped controller trigger; fish encounters use the nibble/bite/catch sequence below. Rod appearance, controller alignment and comfort need Quest testing. Tests in `tests/fishing/rods.mjs` cover continuous curve deformation, taper, controls, tracking/session behavior and line attachment.


Bobber physics: `LinePhysics.mjs` uses a fixed 120 Hz Verlet/position-based rope with twelve segments, gravity 9.81 m/s², light line nodes and a heavier bobber, damping 0.35/s, and 24 tension-only constraint iterations. The tip is pinned to an interpolated controller-derived world position; slack line never pushes. Persistent Float64 positions and previous positions retain momentum for later casting; `length` supports future payout and `bobberVelocity(out)` exposes velocity. Rendering updates a white thirteen-point line, ending at the bobber surface. Locomotion, ground-height rebasing and flight convert between scene/world space without fake impulses. Hand transfers preserve the active physical state; toggling off, tracking loss, session changes, explicit player resets and teleports over 3 m reinitialize safely. Long frame gaps simulate at most 50 ms. Simultaneous B/Y presses choose right deterministically. Tests cover swing/inertia, finite length, frame rates, large coordinates, payout, hand transfer and rebasing. Quest feel and appearance require headset testing.


## Trigger casting and reeling

With a rod shown, hold that hand's trigger to arm a cast, swing, and release. Launch velocity comes from the bobber's constrained swing. The bobber pays out line only when it exhausts the available slack and pulls outward; a small spool resistance slows payout. The maximum remains 125 feet (38.1 m). Holding the trigger again winds the available line onto the spool, ramping from 0.5 to 10 m/s over five seconds; release stops winding and resets that ramp. Slack can wind in without moving the bobber. Once taut, the line constraint supplies position and velocity impulses that pull the bobber inward. Winding stops at the 2-foot (0.6096 m) minimum without resetting positions, momentum, tension or the physics solver. The bobber continues swinging/floating on the same constrained line. A fresh trigger press can arm another cast after releasing the retrieval trigger.

Water and terrain now have separate samplers. Gravity always acts on a cast bobber. Submerged sphere volume determines buoyancy (one-eighth immersion balances gravity), with strong immersion-dependent water drag (120/s at full immersion). Impacts dip briefly before settling with the centre about 2.5 cm above water. Tests at initial downward speeds of 5–15 m/s and display rates of 30–120 Hz keep the centre less than 11 cm below water; no artificial depth clamp is used. Terrain retains swept contact and friction, including shoreline retrieval. Intermediate line nodes do not have water or terrain collisions.

The simulation uses twelve line segments, 120 Hz fixed steps, 24 rope iterations, reusable Float64 buffers and the six-step frame limit. To keep cost bounded, the bobber uses an effective taut tip-to-bobber length constraint; the intermediate nodes provide the slack/sag shape with a pinned endpoint. This is an approximation rather than a fully coupled elastic rope. Tension is estimated from constraint impulses, filtered, and drives the continuous rod curve with a smooth response. No additional draw calls or runtime geometry are introduced.

Only the equipped xr-standard controller's button 0 controls casting/reeling, with 0.6/0.15 trigger hysteresis. Hand transfer preserves physics and synchronizes trigger state. Tracking loss, hiding equipment, session changes, player resets and large teleports reset safely. World-coordinate simulation preserves motion across terrain rebasing. Tests cover slack retrieval, tension impulses, payout, cap, submersion/recovery, water-to-shore retrieval, frame rates, controller integration, and speed ramping. Quest appearance and performance require headset testing.

A local Node comparison using the actual terrain sampler and repeated casting/retrieval measured about 0.0074 ms per fixed step before and 0.0076 ms after (three warmed samples). This measures physics only on the development computer, not Quest frame time.

Trigger action is latched at each press from the paid-out line length: above the 2-foot minimum winds while held, and at minimum arms a cast that launches on release. Below 2 metres, final retrieval finishes automatically even after release. Above that threshold, releasing retrieval stops winding; it never launches or opens the spool, including after reaching minimum during the hold. After retrieval the same endpoint solver retains momentum, with tension computed relative to rod-tip motion so new controller swings can launch repeated casts. Regression tests run three retrieval/recast cycles at 30/72/90/120 Hz.

Retrieval tapers winding speed quadratically over the final 2 metres to a 0.30 m/s floor, reaching the minimum without a pose reset. During the final two-metre approach, extra bobber/line damping ramps quadratically up to 3/s as remaining line shrinks. At minimum length that damping continues at full strength without a gap. Pressing to arm a cast immediately disables this extra damping without altering positions or velocity; it remains disabled throughout the cast. Existing air/water drag remains unchanged. Tests compare identical settled/non-settled physical states during casting at 30/72/90/120 Hz to verify the settling damper cannot weaken a cast.

Approach damping remains active during automatic final retrieval and at the fully retrieved minimum. Arming a new cast disables extra damping immediately; an outbound open spool remains undamped.

Reeling gives the equipped controller one light haptic pulse (0.12 intensity, 50 ms) when retrieval reaches the two-foot minimum. A completion counter prevents repeats while held or settled; showing/resetting/hand transfer alone does not pulse. Missing, throwing or rejected haptic actuators are ignored safely.

Rod shaft uses a uniform dark gray material (#383838), with no colored segment bands. The separate brown cork-style grip is retained.

Rod bending now uses a single arc-length centreline with tangent angle proportional to squared distance along the shaft. Simpson integration at 32 longitudinal intervals preserves its 2.1 m length; curvature increases continuously from a stiff handle toward the tip. Circular cross-sections and normals rotate with the tangent. Reusable rest-position/normal arrays and curve buffers update the small mesh only when bend changes; bones and skinning are removed. The line attaches to the exact transformed curve endpoint. Geometry density and draw-call count are unchanged. Tests verify monotonic curvature, near-constant length, circular sections and attachment through player transforms. Headset appearance/performance still require user checking.

Fishing tackle: the 25 cm white leader has two flexible 12.5 cm segments, ending at the eye of a small silver J-shaped hook. `LeaderPhysics.mjs` simulates four world-coordinate points (bobber attachment, leader joint, hook eye, hook bend/mass) at 120 Hz with gravity, air/underwater drag and 24 lightweight constraint iterations. The two leader links only pull; the final hook link holds a rigid length and drives hook orientation. The bobber drives the tackle without reaction forces, preserving the current casting feel. Persistent Float64 buffers support world rebasing; hand transfers preserve the tackle simulation, while hidden/reset/teleport states reinitialize it. No surface collisions are added. `hookAnchor` (FishAttachment) follows the moving hook bend and `hookWorldPosition` exposes its logical position for fish. Two leader segments share one draw call, plus one for the hook. Tests cover articulation, link lengths, frame rates, underwater damping, attachment, world precision and reset behavior.


Fish encounters: `FishEncounter.mjs` owns a lightweight state machine with injectable randomness and central `FISHING_RULES` for future bait/location tuning. A cast bobber with at least 2 metres of line must settle on actual water (under 0.12 m/s for 0.4 seconds, near the surface, with the hook submerged). After a random 3–6 second wait, it nibbles 2–7 times with random 0.5–2 second gaps, including a gap before the bite. Nibbles produce light pulses (0.12, 50 ms), and bites produce strong vibration (0.8, 300 ms) with a one-second retrieval window. Main line and leader stay white in all phases. The separate retrieval-completion pulse remains active. Reeling before a bite cancels the encounter; missing the bite restarts the wait. Only actual retrieval, rather than a casting trigger press, hooks a biting fish.

A successful hook replaces the hook mesh with a small procedural fish following the articulated hook anchor. It uses the existing tackle physics, with no fish fighting/load changes yet. Once fully retrieved to the 2-foot minimum, the fish remains on the line for two seconds, then fades over one second; the hook returns and normal fishing resumes. Casting is disabled throughout the hold/fade, with a fresh trigger press required afterward; an already held retrieval may finish winding to minimum. Each hooked fish gets a random body hue with matching darker fins, retained through retrieval, hand transfer and fading. Explicitly hiding/resetting equipment or teleporting cancels encounters safely; transient source/pose gaps retain the last world pose and continue the encounter and hand transfer preserves it and directs subsequent pulses to the new controller. Hidden diagnostics include the fish phase. Tests cover timing/count ranges, early retrieval, missed/late bites, complete repeated cycles, fish haptic strengths for either hand, actual bobber-to-catch integration, anchor following, fading and resets. Headset visuals and haptic feel still need user testing.


Quest nibble disappearance diagnosis: a live CDP trace recorded a nibble, then XR input-source disconnects 0.54 seconds later while viewer tracking remained valid; the disconnect handler cleared `shown` and reset tackle, and sources reconnected about 1.2 seconds later (with controller index ordering changed). `RodSystem` now preserves equipment intent and physical/encounter state across source replacement, matches the returning equipped hand independent of controller index, and continues simulation using the last known logical world pose while unavailable. The cached rod pose has no timeout and stays independent of player rig motion and terrain rebasing. Missing controller inputs cancel held actions without launching casts; simulation, bite windows and catch fading continue normally. Haptics use the last equipped actuator when no current source is available, ignoring errors. Session exit and explicit B/Y hiding still reset normally. Missing input sources no longer synthesize button releases. Regression coverage reproduces disconnect/reconnect during nibbling with reversed controller indices, no B/Y press, and checks encounter/physics continuity.

Nibble/bite bobber cues: each nibble requests a 1-inch (0.0254 m) dip; each bite requests a 6-inch (0.1524 m) dip. A short fish pull shifts buoyancy equilibrium downward, bounds the pull depth relative to its starting position, then releases so natural buoyancy returns the bobber. Main-line constraints and terrain contact remain active, and the leader follows the actual moving bobber. Self-induced nibble motion does not cancel the encounter. Tests check both depths and recovery across 30/72/90/120 Hz.

While a fish is hooked and not yet retrieved, the rod controller receives moderate sustained feedback (0.30 intensity, 120 ms pulses renewed every 80 ms). Buzzing stops immediately once line length reaches 2 metres, before automatic final retrieval finishes at the 2-foot minimum; the two-second hold and one-second fade are silent except for the separate retrieval-completion pulse. Hiding equipment, session exit and resets stop buzzing; controller hand/actuator changes stop the old actuator and move feedback to the new one.

General slack control: paid-out main line may exceed straight rod-tip/bobber distance by up to 6 inches (0.1524 m). Surplus beyond that allowance is taken up smoothly over one second, continuously in flight, on water, on land and during retrieval. It never shortens below endpoint separation plus the allowance, so take-up does not itself pull the bobber. Normal trigger retrieval remains available; the old water-landing timer and input lockout are removed. Tests verify the allowance, convergence time, no needless take-up and operation in air/land/retrieval.

Automatic final retrieval activates below 2 metres once manual retrieval has begun or an outbound cast has landed on water. It finishes to the 2-foot minimum without holding the trigger. It never interrupts casting preparation or initial outbound flight. Casting requires the minimum length, with no former 2–3-foot zone; the fish display/fade and completion pulse also begin at minimum.

Bite indicator: a camera-facing FISH! quad appears centered 2.4 m above the bobber when a bite begins. `BiteLabel.js` rasterizes bold red, dark-outlined system-font text into a transparent 512×160 canvas texture once on first display; no font asset or external request is required. The label is 9 m wide (ten times its original size), pulses smoothly ±15% at 2 Hz, follows the bobber and remains visible for a full second from bite onset even after hooking or a missed bite, then shrinks smoothly to zero over the next second and hides. Reset/equipment hiding cancels the label; hand transfer preserves its animation. Its texture/material are disposed with the rod.

Each new hooked fish draws an independent uniform size multiplier from 0.5–2.5, stored alongside its random hue in the encounter so it persists through retrieval, hand transfer and fading. Scaling is about the mouth attachment point. At hooking, fish weight is stored in kilograms as baseWeightKg × size³, using 0.35 kg at original size. Weight drives a saturating rod load of 0.75 × weight/(weight + 0.75), combined with line tension; it no longer uses visual size directly. Larger/heavier fish bend it more, while no-fish casting retains its existing tension response. The added load fades with the fish. This does not change fish/tackle mass or retrieval speed. Size limits and reference weight live in FISHING_RULES. Weight persists with the encounter through hand transfers, retrieval and fading, ready for future fighting-strength integration.

Fish mouth alignment: the fish origin is at the leader endpoint/hook eye, with the body tip exactly at that origin. Size scaling and hook rotation preserve the connection with no gap. The physical hook-bend anchor remains available separately for load/attachment calculations.

Missed-fish indicator: bite timeout or retrieval before a bite replaces FISH! with a blue LOST! quad. It floats upward 1.6 m and smoothly shrinks to zero over two seconds, then hides. Label textures are generated lazily once per message and reused; reset/hiding cancels the animation and hand transfer preserves it. A subsequent bite restores red FISH!.

LOST! is emitted once per actual missed bite or interrupted nibbling fish. Reeling during the random waiting delay only cancels that delay; it cannot lose another fish or restart an existing LOST! animation. Regression coverage presses the trigger repeatedly during the post-loss waiting period and verifies the original animation finishes normally.
