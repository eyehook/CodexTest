## Fishing — independent Terrain fork

Fishing is the foundation for a fishing simulator, initially duplicating Terrain’s landscape, lakes, trees, controls, diagnostics and flight. Source: `src/fishing/`; static build/config and documentation: `projects/fishing/`; independent baseline tests: `tests/fishing/`. Root commands: `pnpm dev:fishing` (5175), `pnpm build:fishing`, `pnpm test:fishing`; root `test` includes Fishing. Gameplay modules are copied, not imported from Terrain; flight physics are also copied locally as `flight-physics.mjs`. Three.js uses the licensed repository-level `shared/vendor/three-r180/` bundle. Keep Fishing independent as it diverges. Fishing now includes a first nibble/bite/catch loop. Keep generated outputs with source for Pages, test locally/on Quest, and publish only when requested. No Fishing headset validation has been recorded.


Fishing lighthouse: `src/fishing/Lighthouse.js` loads the locally copied Blender GLB at 2× exported scale, anchored to terrain by its authored `Base` empty node. `lighthouse-placement.mjs` selects a deterministic coastal hill near initial spawn; default X −171/Z −60, 113 m from player, about 24 m above water. The model extends below Base into the terrain; no separate foundation is generated. Terrain noise/height changes relocate it; per-frame position subtracts logical world X/Z and ground height (room-scale tracking remains in rig coordinates). Desktop starts facing it. Source asset is bundled by Vite; retain generated GLB with build. Tests cover placement, actual GLB parsing, Base anchoring through parent transforms, and world rebasing. No collision or lighthouse beam yet.


Fishing grass: `src/fishing/grass/` uses a fixed pool of 156 terrain patches, each 8 m square with up to 320 blades (49,920 instance slots, within the 50,000 cap). One jittered candidate per 0.5 m × 0.4 m rectangle creates uniform world density on green land only, above beachEnd and below snowStart. A 2 m shader edge shrink limits visibility to 150 feet (45.72 m). Patch selection includes a conservative movement margin, preserving the full circle between 2 m refreshes; invisible margin blades still occupy slots. Terrain placement is deterministic and available everywhere as the player travels. Heights are 9–21 cm with varied widths, angles and greens. No textures, wind, shadows or collision.

CPU streaming: preallocated patch objects, typed request/free arrays and dirty flags replace per-blade Maps/Sets, distance selection and sorting. Retained patches keep their slot; only entering patches generate heights, bounded to 128 candidates per frame, nearest unfinished patches first. Patches generate over multiple frames and upload only on completion. A single instanced interleaved GPU buffer packs position, size, color and orientation. Dirty patch blocks use one merged upload range, preserving changes not yet rendered. Ordinary frames update uniforms only, except rare coordinate rebasing beyond 1,024 m. New/teleported areas fill progressively; invalidating terrain clears old blades. No worker is used in this version.

Grass comparison: The Terrain controls checkbox or G on desktop toggles rendering and streaming. B/Y have no grass action. A/X flight is unchanged; Fishing controller triggers have no speed action. Walking speed is set through terrain controls (6 m/s default). Hidden DOM diagnostics report submitted eligible blades (including the margin), selection/generation/buffer preparation CPU milliseconds (S/G/B), total/peak grass update time, queued patches and upload count. These timings exclude GPU execution and driver work during rendering. Unit tests cover fixed-pool coverage, biome exclusion, reproducibility, per-frame generation budget, retained slots, consolidated uploads, toggle suspension, teleports and billion-metre rebasing.

Three desktop 1,800-frame walking CPU checks measured total grass-update time of 45–87 ms before versus 9–19 ms with fixed patches (roughly 80% lower in these samples). This is a local Node CPU check, not a headset FPS or GPU benchmark. All grass uses one double-sided opaque draw batch; fixed slots can process more invisible triangles than the previous selection. Quest appearance, CPU/GPU balance and performance still need physical comparison.


Fishing flight now uses local tuning in `flight-physics.mjs`: A/X applies 7.5 m/s² thrust against 1.5 m/s² gravity (6 m/s² net), capped at 3 m/s ascent; descent cap remains 1.5 m/s. Full-speed release gains up to 3 m over 2 s before descent. `player.mjs` provides `updateHorizontalMotion`: input approaches head-relative world velocity smoothly (4/s response); reducing aligned stick input or releasing it integrates gentler exponential drag (0.8/s). This prevents a returning analog stick from erasing momentum before centring. Grounded input/release remain immediate. Turning the head without stick input preserves glide direction. Landing, XR start/end and Return to origin clear horizontal momentum; hidden/untracked frames pause motion. Desktop walking is unchanged. Diagnostics report actual horizontal velocity, including glide. Flight/glide tests cover frame independence, A/X equivalence, fixed airborne altitude across terrain, landing and input gating. Physical Quest flight/comfort checking remains necessary.


Fishing seed changes: Apply compares old/new seed and calls `coastalSpawn` in `water.mjs`. Deterministic radial sampling plus bisection finds terrain above water by min(1 m, amplitude × .02), with a verified water sample within 96 m. Relocation compensates current XR horizontal tracking and clears flight/glide via `resetFlight`. Coastless settings reject the apply and restore prior numeric settings; unchanged seed does not respawn. Initial dry spawn and Return to origin are unchanged. `tests/fishing/spawn.mjs` covers multiple seeds, varied height settings, nearby actual water and flat-terrain rejection.


Fishing rods: `src/fishing/rods/` adds procedural continuous-curve `FishingRod` meshes with grip, dynamic line and red/white bobber. B/right and Y/left toggle exclusively using button 5; initial/session-ended state is hidden; temporary controller reconnections retain equipment. `RodSystem` attaches each rod to its actual handed controller grip under the player rig and checks grip poses before showing equipment. Line/bobber physics runs in double-precision world coordinates; rendering converts it back to scene coordinates. The minimum line length is 2 feet (0.6096 m), with trigger casting, water/terrain contact and reeling; fish encounters use the nibble/bite/catch sequence below. `setBend(hand, 0..1)` is ready for load-driven bend integration. A/X flight remains unchanged. Tests verify actual curve vertex deformation, taper, line endpoints, mutually exclusive press latches and pose/disconnection/session gating. Headset alignment/appearance need user testing.


Bobber physics: `LinePhysics.mjs` uses a fixed 120 Hz Verlet/position-based rope with twelve segments, gravity 9.81 m/s², light line nodes and a heavier bobber, damping 0.35/s, and 24 tension-only constraint iterations. The tip is pinned to an interpolated controller-derived world position; slack line never pushes. Persistent Float64 positions and previous positions retain momentum for later casting; `length` supports future payout and `bobberVelocity(out)` exposes velocity. Rendering updates a white thirteen-point line, ending at the bobber surface. Locomotion, ground-height rebasing and flight convert between scene/world space without fake impulses. Hand transfers preserve the active physical state; toggling off, tracking loss, session changes, explicit player resets and teleports over 3 m reinitialize safely. Long frame gaps simulate at most 50 ms. Simultaneous B/Y presses choose right deterministically. Tests cover swing/inertia, finite length, frame rates, large coordinates, payout, hand transfer and rebasing. Quest feel and appearance require headset testing.

## Trigger casting and reeling

With a rod shown, hold that hand's trigger to arm a cast, swing, and release. Launch velocity comes from the bobber's constrained swing. The bobber pays out line only when it exhausts the available slack and pulls outward; a small spool resistance slows payout. The maximum remains 125 feet (38.1 m). Holding the trigger again winds the available line onto the spool, ramping from 0.5 to 10 m/s over five seconds; release stops winding and resets that ramp. Slack can wind in without moving the bobber. Once taut, the line constraint supplies position and velocity impulses that pull the bobber inward. Winding stops at the 2-foot (0.6096 m) minimum without resetting positions, momentum, tension or the physics solver. The bobber continues swinging/floating on the same constrained line. A fresh trigger press can arm another cast after releasing the retrieval trigger.

Water and terrain now have separate samplers. Gravity always acts on a cast bobber. Submerged sphere volume determines buoyancy (one-eighth immersion balances gravity), with strong immersion-dependent water drag (120/s at full immersion). Impacts dip briefly before settling with the centre about 2.5 cm above water. Tests at initial downward speeds of 5–15 m/s and display rates of 30–120 Hz keep the centre less than 11 cm below water; no artificial depth clamp is used. Terrain retains swept contact and friction, including shoreline retrieval. Intermediate line nodes do not have water or terrain collisions.

The simulation uses twelve line segments, 120 Hz fixed steps, 24 rope iterations, reusable Float64 buffers and the six-step frame limit. To keep cost bounded, the bobber uses an effective taut tip-to-bobber length constraint; the intermediate nodes provide the slack/sag shape with a pinned endpoint. This is an approximation rather than a fully coupled elastic rope. Tension is estimated from constraint impulses, filtered, and drives the continuous rod curve with a smooth response. No additional draw calls or runtime geometry are introduced.

Only the equipped xr-standard controller's button 0 controls casting/reeling, with 0.6/0.15 trigger hysteresis. Hand transfer preserves physics and synchronizes trigger state. Tracking loss, hiding equipment, session changes, player resets and large teleports reset safely. World-coordinate simulation preserves motion across terrain rebasing. Tests cover slack retrieval, tension impulses, payout, cap, submersion/recovery, water-to-shore retrieval, frame rates, controller integration, and speed ramping. Quest appearance and performance require headset testing.

A local Node comparison using the actual terrain sampler and repeated casting/retrieval measured about 0.0074 ms per fixed step before and 0.0076 ms after (three warmed samples). This measures physics only on the development computer, not Quest frame time.

Trigger action is latched at each press from the paid-out line length: above the 2-foot minimum winds while held, and at minimum arms a cast that launches on release. Below 2 metres, final retrieval finishes automatically even after release. Above that threshold, releasing retrieval stops winding; it never launches or opens the spool, including after reaching minimum during the hold. After retrieval the same endpoint solver retains momentum, with tension computed relative to rod-tip motion so new controller swings can launch repeated casts. Regression tests run three retrieval/recast cycles at 30/72/90/120 Hz.

Retrieval tapers winding speed quadratically over the final 2 metres to a 0.30 m/s floor, reaching the minimum without a pose reset. During the final two-metre approach, extra bobber/line damping ramps quadratically up to 3/s as remaining line shrinks. At minimum length that damping continues at full strength without a gap. Pressing to arm a cast immediately disables this extra damping without altering positions or velocity; it remains disabled throughout the cast. Existing air/water drag remains unchanged. Tests compare identical settled/non-settled physical states during casting at 30/72/90/120 Hz to verify the settling damper cannot weaken a cast.

Approach damping remains active during automatic final retrieval and at the fully retrieved minimum. Arming a new cast disables extra damping immediately; an outbound open spool remains undamped.

Reeling gives the equipped controller one light haptic pulse (0.12 intensity, 50 ms) when retrieval reaches the two-foot minimum. A completion counter prevents repeats while held or settled; showing/resetting/hand transfer alone does not pulse. Missing, throwing or rejected haptic actuators are ignored safely.

Rod shaft uses a uniform dark gray material (#383838), with no colored segment bands. The separate brown cork-style grip is retained.

Rod bending now uses a single arc-length centreline with tangent angle proportional to squared distance along the shaft. Simpson integration at 32 longitudinal intervals preserves its 2.1 m length; curvature increases continuously from a stiff handle toward the tip. Circular cross-sections and normals rotate with the tangent. Reusable rest-position/normal arrays and curve buffers update the small mesh only when bend changes; bones and skinning are removed. The line attaches to the exact transformed curve endpoint. Geometry density and draw-call count are unchanged. Tests verify monotonic curvature, near-constant length, circular sections and attachment through player transforms. Headset appearance/performance still require user checking.

Fishing tackle: the 25 cm white leader has two flexible 12.5 cm segments, ending at the eye of a small silver J-shaped hook. `LeaderPhysics.mjs` simulates four world-coordinate points (bobber attachment, leader joint, hook eye, hook bend/mass) at 120 Hz with gravity, air/underwater drag and 24 lightweight constraint iterations. The two leader links only pull; the final hook link holds a rigid length and drives hook orientation. The bobber drives the tackle without reaction forces, preserving the current casting feel. Persistent Float64 buffers support world rebasing; hand transfers preserve the tackle simulation, while hidden/reset/teleport states reinitialize it. No surface collisions are added. `hookAnchor` (FishAttachment) follows the moving hook bend and `hookWorldPosition` exposes its logical position for fish. Two leader segments share one draw call, plus one for the hook. Tests cover articulation, link lengths, frame rates, underwater damping, attachment, world precision and reset behavior.


Fish encounters: `FishEncounter.mjs` owns a lightweight state machine with injectable randomness and central `FISHING_RULES` for future bait/location tuning. A cast bobber with at least 2 metres of line must settle on actual water (under 0.12 m/s for 0.4 seconds, near the surface, with the hook submerged). After a random 3–6 second wait, it nibbles 2–7 times with random 0.5–2 second gaps, including a gap before the bite. Nibbles produce light pulses (0.12, 50 ms), and bites produce strong vibration (0.8, 300 ms) with a one-second retrieval window. Main line and leader stay white in all phases. The separate retrieval-completion pulse remains active. Reeling before a bite cancels the encounter; missing the bite restarts the wait. Only actual retrieval, rather than a casting trigger press, hooks a biting fish.

A successful hook replaces the hook mesh with a small procedural fish following the articulated hook anchor. It uses the existing tackle physics, with no fish fighting/load changes yet. Once fully retrieved to the 2-foot minimum, the fish remains on the line for two seconds, then fades over one second; the hook returns and normal fishing resumes. Casting is disabled throughout the hold/fade, with a fresh trigger press required afterward; an already held retrieval may finish winding to minimum. Each hooked fish gets a random body hue with matching darker fins, retained through retrieval, hand transfer and fading. Explicitly hiding/resetting equipment or teleporting cancels encounters safely; transient source/pose gaps retain the last world pose and continue the encounter and hand transfer preserves it and directs subsequent pulses to the new controller. Hidden diagnostics include the fish phase. Tests cover timing/count ranges, early retrieval, missed/late bites, complete repeated cycles, fish haptic strengths for either hand, actual bobber-to-catch integration, anchor following, fading and resets. Headset visuals and haptic feel still need user testing.


Quest nibble disappearance diagnosis: a live CDP trace recorded a nibble, then XR input-source disconnects 0.54 seconds later while viewer tracking remained valid; the disconnect handler cleared `shown` and reset tackle, and sources reconnected about 1.2 seconds later (with controller index ordering changed). `RodSystem` now preserves equipment intent and physical/encounter state across source replacement, matches the returning equipped hand independent of controller index, and continues simulation using the last known logical world pose while unavailable. The cached rod pose has no timeout and stays independent of player rig motion and terrain rebasing. Missing controller inputs cancel held actions without launching casts; simulation, bite windows and catch fading continue normally. Haptics use the last equipped actuator when no current source is available, ignoring errors. Session exit and explicit B/Y hiding still reset normally. Missing input sources no longer synthesize button releases. Regression coverage reproduces disconnect/reconnect during nibbling with reversed controller indices, no B/Y press, and checks encounter/physics continuity.

Nibble/bite bobber cues: each nibble requests a 1-inch (0.0254 m) dip; each bite requests a 6-inch (0.1524 m) dip. A short fish pull shifts buoyancy equilibrium downward, bounds the pull depth relative to its starting position, then releases so natural buoyancy returns the bobber. Main-line constraints and terrain contact remain active, and the leader follows the actual moving bobber. Self-induced nibble motion does not cancel the encounter. Tests check both depths and recovery across 30/72/90/120 Hz.

While a fish is hooked and not yet retrieved, the rod controller receives moderate sustained feedback (0.30 intensity, 120 ms pulses renewed every 80 ms). Buzzing stops immediately once line length reaches 2 metres, before automatic final retrieval finishes at the 2-foot minimum; the two-second hold and one-second fade are silent except for the separate retrieval-completion pulse. Hiding equipment, session exit and resets stop buzzing; controller hand/actuator changes stop the old actuator and move feedback to the new one.

General slack control: paid-out main line may exceed straight rod-tip/bobber distance by up to 6 inches (0.1524 m). Surplus beyond that allowance is taken up smoothly over one second, continuously in flight, on water, on land and during retrieval. It never shortens below endpoint separation plus the allowance, so take-up does not itself pull the bobber. Normal trigger retrieval remains available; the old water-landing timer and input lockout are removed. Tests verify the allowance, convergence time, no needless take-up and operation in air/land/retrieval.

Automatic final retrieval activates below 2 metres once manual retrieval has begun or an outbound cast has landed on water. It finishes to the 2-foot minimum without holding the trigger. It never interrupts casting preparation or initial outbound flight. Casting requires the minimum length, with no former 2–3-foot zone; the fish display/fade and completion pulse also begin at minimum.

Bite indicator: a camera-facing FISH! quad appears centered 2.4 m above the bobber when a bite begins. `BiteLabel.js` rasterizes bold red, dark-outlined system-font text into a transparent 512×160 canvas texture once on first display; no font asset or external request is required. The label is 9 m wide (ten times its original size), pulses smoothly ±15% at 2 Hz, follows the bobber and remains visible for a full second from bite onset even after hooking or a missed bite, then shrinks smoothly to zero over the next second and hides. Reset/equipment hiding cancels the label; hand transfer preserves its animation. Its texture/material are disposed with the rod.

Each new hooked fish draws an independent uniform size multiplier from 0.5–2.5, stored alongside its random hue in the encounter so it persists through retrieval, hand transfer and fading. Scaling is about the mouth attachment point. At hooking, fish weight is stored in kilograms as baseWeightKg × size³, using 0.35 kg at original size. Weight drives a saturating rod load of 0.75 × weight/(weight + 0.75), combined with line tension; it no longer uses visual size directly. Larger/heavier fish bend it more, while no-fish casting retains its existing tension response. The added load fades with the fish. This does not change fish/tackle mass or retrieval speed. Size limits and reference weight live in FISHING_RULES. Weight persists with the encounter through hand transfers, retrieval and fading, ready for future fighting-strength integration.

Fish mouth alignment: the fish origin is at the leader endpoint/hook eye, with the body tip exactly at that origin. Size scaling and hook rotation preserve the connection with no gap. The physical hook-bend anchor remains available separately for load/attachment calculations.

Missed-fish indicator: bite timeout or retrieval before a bite replaces FISH! with a blue LOST! quad. It floats upward 1.6 m and smoothly shrinks to zero over two seconds, then hides. Label textures are generated lazily once per message and reused; reset/hiding cancels the animation and hand transfer preserves it. A subsequent bite restores red FISH!.

LOST! is emitted once per actual missed bite or interrupted nibbling fish. Reeling during the random waiting delay only cancels that delay; it cannot lose another fish or restart an existing LOST! animation. Regression coverage presses the trigger repeatedly during the post-loss waiting period and verifies the original animation finishes normally.
